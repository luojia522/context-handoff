# 上下文交接规程（重启人机结合系统 · memory 件）

实证来源：压缩观测日志 001 号（2026-08-28 系统压缩无损幸存，四件落实包零障碍接续）。生态佐证：DSH 1024Store memory 类居安装榜头部——「agent 记不住」是全生态刚需。

## 一、交（断线／压缩前自报）——最小完备五栏

会话将断、主题收口、或长任务告一段落时，把「接续现场笔记」更新为五栏：

1. **当前口令**——正在执行的任务＋下一步第一步（管下一步）；
2. **勿重做清单**——已销账事项（防重复劳动）；
3. **勿 reopen 边界**——已定纪律与候裁项（防重复请示）；
4. **工具链要点**——已验证的通道、脚本、会话名与用法（勿重发明）；
5. **缺口与风险**——没做成、不确定、失败通道（如实挂账）。

写法铁则：**写给一个零上下文的接手者**——路径写绝对、版本钉号码、动作带命令。

## 二、接（新会话载入）——四步验收

1. 读接续现场笔记＋工作单（唯一活账）；
2. 按装机清单逐项核对在位（见第三节）；
3. **自报四点**：当前模式／活账位置／候裁项／下一刀——然后停住等口令；
4. **回读验收对物证不对自述**：交接摘要只是线索，必须用 git log、落盘文件、登记簿交叉验证后才可信。压缩会抹去自身痕迹——轮数等计数要靠外部账本，不凭记忆。

## 三、装机清单核对——失败报告式

读 `装机清单.json`，逐 entry 核对：path 存在／会话可用／版本相符。缺失项**不硬撑**，按三栏列出报人：

| 路径 | 预期 | 现状 |
|---|---|---|

（格式借 Minecraft mrpack 失败下载报告与 DSH 条目 schema——他山 V0.5/V0.6。）

## 四、压缩观测立档

每次上下文压缩皆立 00N 号档案：事件、可见轮数口径、幸存清单（回读验收）、缺口分析、规程修订。主动节奏：**主题收口即盘点入仓，赶在系统强制压缩之前**——被动压缩时机不可控，主动压缩自己掌握。

## 五、DSH 适配口（预留，未实现）

本规程与载体无关，挂入 DSH 时只需一个薄适配层：

- DSH 会话 start/end 事件 → 触发「接」／「交」；
- DSH 事件溯源（event sourcing）流 → 兼任出入库登记簿的物证源；
- 清单条目按 DSH 插件 schema 补 `install` 一行命令；
- **铁律二不可适配**：判断与裁决永留人侧，适配层不得代裁。

## 六、纪律锚点

判断「什么值得留住」是性智取舍；把取舍编码成机器可读格式是量智工程——本规程是两层之间的接口协议，不是自动化裁员。凡呈裁点（定稿、对外发送、覆盖真身）仍须人来下。
